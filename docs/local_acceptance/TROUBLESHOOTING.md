# 失败、未配置与重复执行

状态：`CURRENT_POST49_REFERENCE`

| 状态/退出码 | 含义与处理 |
|---|---|
| PASSED / 0 | 该阶段条件满足；具体范围见scope，不自动代表性能提高 |
| PARTIAL / 2 | 完成部分输出，例如检索回退或没有命中；保留警告 |
| BLOCKED / 2 | 缺依赖、服务、输入、批准或前置阶段；不是误判为成功 |
| FAILED / 1 | 实际执行或输出校验失败，检查 stderr.log 和子进程日志 |
| NOT_RUN | 没有尝试该阶段，不能计作跳过后通过 |

## 只想看某一步

`run 12-localization` 默认先做输入和真实模型推理，再导出定位。已通过步骤校验哈希后复用。`--no-deps` 仅禁止自动执行前置，不允许绕过前置成功要求。

## 上次失败，想重跑

```bash
python scripts/acceptance/run.py run 40-model-train --workspace ../AstroGraph-local/demo01 --retry --no-deps
```

旧尝试移动到 `attempts/<阶段>/<时间>/`，不会删除证据。若某依赖已经重跑，下游回执的依赖哈希会失效，下游也需要 `--retry`。不加 `--no-deps` 会按同一规则重跑所选阶段及其前置。代码或配置正式更新后建议新建工作区。

未完成任务不自动恢复未知副作用；运行锁 `.runner.lock` 存在时先确认原进程是否仍在运行，不要一边执行一边删除锁。一个工作区不支持并发写。

## 外部工具没有配置

正常行为是 BLOCKED。不要把36阶段的本地协议夹具报告替代真实服务验收。新增端点/模型配置请新建工作区，显式 `--settings`，不要修改已冻结工作区来绕过哈希检查。

## 模型或通道错误

01阶段检查文件与宿主批准；10阶段调用真实原生准备器检查语义和通道。继续使用旧v1模型会被原加载器拒绝。样例使用随包v2权重；新模型要在自己的宿主配置显式批准哈希，不能由验收脚本自动信任。

使用自己的遥测必须同时提供 `--source` 和 `--nominal`。不能用自己的故障数据配默认健康参照。当前原生验收并不保证任意卫星或任意字段可用。

## 训练没有获批

`init` 不批准训练。执行 `approve-training` 后对40阶段 `--retry`。批准的是精确训练清单及其数据哈希，不是模型发布权限。微型演示没有测试集，也不提供ADCS真实性能结论。

## 指标复算失败

51阶段读取的是JSON数组形式的 `joined_evaluation.json`；无标签JSONL不够计算指标。55阶段需要解压后的对比目录；不要把ZIP路径直接传作目录。新回放的无标签输出必须在独立评价侧连接真值。

## 安装或平台问题

可先执行 `python -m pip install -e ".[test,ml,deep-learning,api]"`。默认验收不需要DOR/PPL/LangGraph/在线LLM。缺少模型相关库时对应阶段BLOCKED，不改成伪推理。脚本跨平台设计使用当前Python解释器；本轮实际操作系统见环境回执，未实测平台不宣称通过。

`verify_source.py`是源码内容校验，`60-regression`是选定模式和验收工具回归，原 `verify_release.py`/`run_tests.*` 涉及完整历史测试和外部资料，三者不能混为“全仓通过”。
