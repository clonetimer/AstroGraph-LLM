## 3. P2 如何使用

在便携“开始分析”，或完整平台的新建任务界面展开“工作区与已审阅上下文”。创建工作区时填写名称，可选设备、事件；添加人工补充说明或模型假设，注明来源。修订生成新版本并重新进入待审状态。审阅后，明确勾选本次需要的条目，再提交诊断文件。

工作区选择不等于自动注入全部历史内容。未勾选、草稿、错误版本和其他工作区的条目不会进入本次分析。最多选择 8 条、总正文 32,000 字符。任务创建时冻结内容和版本；之后修改原条目不改写已保存报告，追问仍使用该任务快照。

完整平台中：查看沿用现有读取权限；创建和修订要求操作权限；审阅要求 reviewer 权限，身份来自服务端认证。便携版是单机单用户工作台，不把本地“审阅”说成独立专家认证。审阅表示同意作为分析上下文，不代表故障事实正确。工作区用于内容范围控制，不承诺新增多租户隔离。

原始文件和来源 ID 不被笔记替换。模型仍需引用任务原始来源；人工说明与模型假设不会自动成为已确认故障。

## 4. P3 如何使用（当前为便携源码入口）

“模型设置”保留原单模型方式；展开阶段模型设置，可指定片段分析、综合分析、追问的模型 ID，留空继承主模型。界面使用同一服务/凭据；API 覆盖服务地址时，未明确提供的 API Key 不从原服务继承。没有隐式云端切换、模型失败后的自动换模型或难度判别模型。

提交任务前可勾选排队。服务同时执行 1 个任务，最多等待 8 个；未勾选时忙碌仍明确拒绝。等待任务可以取消；执行中的任务在安全检查点停止。已经发出的模型请求可能仍完成并产生费用，取消不是撤回供应商账单。取消先于报告发布时不发布最终报告；已完成发布后不把结果倒改为已取消。

重启后，遗留排队/运行任务标为中断，不自动重新付费执行。手动继续需重新提供凭据，并匹配输入、上下文、各阶段模型和执行设置；配置变化拒绝复用原任务。分析运行期间可读取其他工作区、为新排队任务选择上下文，但修改上下文和备份恢复要求空闲。

## 5. 本轮修复的关键问题

- 新模块和资源未进入便携装配/源码导出，导致 ImportError。
- 旧测试引用不存在的夹具名称、调用方式和线程构造签名，不能据此宣称真实集成通过。
- 完整平台上下文 JS/CSS 资源地址返回 404；现提供真实可访问路径。
- `/review/` 尾斜杠与 `/review` 权限匹配不一致，已统一，operator 两者均不能审阅。
- 任务上下文绑定未尊重 launch/run 锁；现在拒绝运行中的绑定并只释放本次持有锁。
- 队列活动期间上下文读取被一并阻止，妨碍配置下一任务；现允许 GET，写操作仍限制。
- Python 3.8 中的清单类型注解、Path.is_relative_to、hashlib.file_digest 不兼容已修复；PDF 测试夹具改用确定的 pypdf 文档生成，不改生产解析结果。
- 队列持久化失败不执行 callback；备份恢复发布失败回滚上下文事务；审阅复选框不再被全宽输入样式撑大。

## 6. 从源码试用

最终用户不要覆盖旧 data 或混用 Windows 运行时。已有合适 Python 依赖的开发机，可在完整源码根目录执行：

```shell
python -c "from pathlib import Path; from portable.build import stage_app; stage_app(Path('.'), Path('.local/p2p3-app'))"
python .local/p2p3-app/workbench.py --data-dir .local/p2p3-data --open-browser
```

装配目标必须为空或不存在。此过程不下载运行时、依赖或模型；不能在未准备 Python 的电脑上代替便携安装包。完整平台继续使用仓库 RUN_GUIDE.md 入口。
