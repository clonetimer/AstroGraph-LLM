# AstroGraph-LLM 外部诊断分析工作台 V2.7.1 Preview

这是面向 Windows 10 **64 位 x64** 的便携包。完整解压后即可使用，不需要安装 Python、Node、pip、管理员权限或 GPU。界面只做“外部诊断文本 → 大模型解读 → 来源引用与报告”，不运行遥测检测、诊断计算、故障知识图谱或模型训练。

支持两种模型连接方式：联网调用兼容 OpenAI Chat Completions 的 HTTPS API；或调用本机已经启动的兼容 API 模型服务。**本包不含模型权重，也不含模型服务软件。** 界面本身不需要 GPU；本地模型是否需要 GPU、内存和显存取决于您另外准备的模型服务。

## 一、启动

1. 将整个 ZIP 解压到自己有写入权限的文件夹，例如“文档”中的 AstroGraph 文件夹。不要直接在压缩文件窗口内运行，也不要只复制 START.bat。
2. 双击 `CHECK.bat`，先校验包文件，再执行离线依赖、导入和功能自检。成功时显示 `Offline self-test passed`；结果保存在根目录 `CHECK.log`。这个日志只含自检状态和环境信息，不含诊断材料或密钥。
3. 双击 `START.bat`。程序在本机 `127.0.0.1` 启动，并用默认浏览器打开界面。如果浏览器没有自动打开，请复制控制台显示的本机地址。
4. 使用期间保留控制台窗口。退出时在控制台按 Ctrl+C；关闭浏览器标签页不会停止服务。

请使用已经安装的 Edge 或 Chrome。目标为 Windows 10 x64，建议 22H2；不支持 Windows 7、32 位 Windows 或 ARM 版 Windows。解压路径可以含空格和中文，但文件夹必须允许写入。程序不需要以管理员身份运行。

## 二、左侧导航如何使用

| 导航 | 操作 |
| --- | --- |
| 开始分析 | 粘贴或上传诊断材料，设置角色和分析目标，开始生成报告 |
| 分析结果 | 查看当前任务、原文引用、长文进度、报告下载和失败重试 |
| 历史任务 | 关键词/状态筛选、打开已保存任务、备份和恢复 |
| 证据问答 | 围绕当前报告追问，引用跳回结果页的原文 |
| 模型设置 | 配置在线 API 或本机模型，测试接口、修改高级参数 |
| 使用帮助 | 查看离线上手流程、容量限制和常见问题 |

先到“模型设置”填好连接，再进入“开始分析”。切换导航保留材料、模型信息、API Key 和未发出的当前问题；这只适用于同一网页会话，刷新/重启后仍需重新输入 Key。改选另一历史任务会切换该任务的问答上下文。模型分析进行中可查看其他页面，完成后不会强制跳转。

窄窗口通过左上角菜单展开导航。浏览器前进/后退可以返回页面。点击问答引用会切到“分析结果”展开对应原文。

## 三、连接本地离线模型

“离线”表示大模型服务和模型已经在这台电脑上准备好，本程序不负责下载或启动它们。

1. 先在模型服务软件中加载您已经具备的模型，并开启兼容 OpenAI 的本地 API 服务。
2. 在工作台选择“本地模型”。LM Studio 常见地址为 `http://127.0.0.1:1234/v1`；Ollama 常见地址为 `http://127.0.0.1:11434/v1`。实际地址以服务软件显示的值为准。
3. 点击“测试连接”，选择或填写服务实际返回的**模型 ID**。模型 ID 必须与服务中的名称一致，不能填写任意显示名称。
4. 如果本地服务要求 API Key，填写该服务配置的值；若不要求，可按界面提示留空。
5. 导入材料并点击分析。运行速度由模型、电脑和服务设置决定。

本地模式只接受 loopback 地址，例如 `127.0.0.1` 或 `localhost`，不会因为输入了外部地址而悄悄切换到云端。本工作台不会在启动时调用模型、下载模型或下载 Python 依赖。

## 四、连接在线 API

1. 选择“在线 API”，填写供应商提供的 **HTTPS** Base URL，通常以 `/v1` 结尾；本程序请求 `/chat/completions`，测试连接查询 `/models`。
2. 填写 API Key 和该服务实际支持的模型 ID。某些 API 不提供模型列表，测试连接可能失败；请先核对该服务是否兼容本程序使用的接口。
3. 按服务能力设置输出 token 上限、超时和 JSON 响应格式。默认自动策略会尝试兼容的 JSON 格式；最终输出仍会在本机进行结构与来源引用校验。
4. 点击分析后，选中的诊断材料、分析要求以及后续追问会发往您配置的 API。请确认这些材料适合交给该服务处理；调用费用由该服务计费。

API Key 仅在本次服务进程的内存中使用，不写入保存的设置、任务、报告或控制台。刷新或重启后若需要再次调用，请重新输入连接信息和 Key。模型服务端本身如何处理数据，由您使用的服务决定。

## 五、输入、结果与导出

可以直接粘贴诊断文本，或导入 TXT、MD、JSON、CSV、LOG、PDF、DOCX。请将每份材料明确设为“外部诊断”“补充日志”或“参考资料”；至少需要一份外部诊断。LOG 文件归入日志，参考资料使用 TXT/MD/PDF/DOCX。示例位于 `app/examples/diagnosis_sample.txt`，内容为虚构材料。根目录的 `README_zh-CN.txt` 可直接用记事本打开，内容与本文相同。

支持 UTF-8、带 BOM 的 UTF-8/UTF-16；旧中文文本可在导入时明确选择 GB18030。本界面不接受压缩包或原始遥测。PDF 会按页提取文字；DOCX 保留标题、正文、表格及原始定位。PDF 文件采用随包携带的 pypdf 5.9.0 纯 Python 解析器，不依赖 Poppler；扫描版 PDF 不做自动 OCR，需先 OCR 并人工核验。解析在独立进程中运行，超过 30 秒会停止并给出提示。当前 PDF 库未完成新版安全升级，只导入确认可信的 PDF；不明来源先在受控环境转为纯文本。文件名不能重复，也不能使用路径、Windows 保留名或其他不安全名称。

每次任务最多 8 份诊断、12 份日志、16 份参考资料，总输入上限 4 MiB，解析后正文上限 180,000 字符；分析要求上限 4,000 字符。60,000 字符以内使用一次模型分析；超过后最多 24 个连续片段（每段约 12,000 字符、重叠 600 字符）分块分析，再执行一次综合分析。超出容量会明确拒绝，不会静默截断。各片段完整摘要合计超过 120,000 字符时，综合阶段会明确停止；已完成片段保留检查点。LLM 的摘要仍属于模型概括，不保证逐条保留所有语义。长文任务会产生多次模型调用，费用和耗时高于短报告，实际可用上下文仍取决于模型服务设置。

结果包含报告内容解读、可能原因及反向解释、前提和不确定性、缺失信息、建议核查和来源引用。点击引用可查看原始段落和位置。可以下载 Markdown/JSON；追问记录也可下载。模型调用或校验失败会显示状态与原因代码，原始材料仍保留；任务已保存并不等于模型分析成功。

追问只使用该任务原始来源，不把问题中的断言或过去模型回答当作新证据。每个任务最多 12 次追问尝试，每个问题最多 4,000 字符；历史上下文有额外容量限制。长报告分块分析会在每个片段通过校验后保存检查点；服务重启后任务显示中断，重新配置相同模型模式、服务地址和模型 ID 后，可点击“继续 / 重试分析”，已完成片段不会重复调用。短报告没有分块检查点，继续时会重新执行整份报告分析。模型失败后的重试会更新该失败任务的分析报告，但不会改写原始诊断材料；已经成功的任务不会开放这个重试入口。

**引用校验通过只代表引用编号存在于输入材料，不能证明模型解读、假设或原始报告正确。** 所有模型内容均需专业人员结合原始资料复核，不构成已确认故障或设备操作授权。

## 六、数据与常见问题

任务、原始字节副本、规范化文本、报告和追问历史保存在解压目录的 `data/`。历史任务列表旁提供“备份”下载完整 ZIP（包含任务、原始文件、报告、追问和分块检查点），以及“恢复”导入 ZIP。恢复前会校验清单、文件 SHA-256 和路径；同编号任务拒绝覆盖，已有数据不会被替换。分析或追问进行中，备份和恢复会被拒绝；请先完成当前操作。备份也可在关闭程序后复制整个解压目录。不要在分析过程中手工修改任务文件。

| 现象 | 处理方式 |
|---|---|
| 提示文件不完整、缺 DLL 或找不到模块 | 重新完整解压；检查安全软件是否隔离了文件；先运行 CHECK.bat。不要用系统 Python 替换随包解释器。 |
| 数据目录不可写 | 移到自己的“文档”等可写位置，避免 Program Files、只读目录或受限共享盘。 |
| 连接拒绝/超时 | 检查模型服务已启动、端口与地址正确、模型已加载；核对本机防火墙和服务日志。 |
| API 认证或模型错误 | 核对 Key、Base URL 和服务实际模型 ID；详细提供商错误不在报告中公开。 |
| 输出过长或结构校验失败 | 增加服务允许的输出 token、缩小本次输入或换用能够遵循 JSON 结构的模型；按需要选择 JSON 格式策略。 |
| 中文乱码 | 导入旧文件时选择 GB18030，或先将文件另存为 UTF-8。 |
| 浏览器不能连接 | 保留控制台窗口，使用其实际显示的本机 URL，检查端口是否已被其他程序使用。 |
| 服务重启后任务显示中断 | 长报告可重新连接原模型后点击“继续 / 重试分析”；短报告重新分析。程序不会自动重放模型请求。 |
| 需要迁移或恢复历史任务 | 点击历史列表旁“备份”下载 ZIP；在目标工作台点击“恢复”选择 ZIP。冲突任务不会覆盖。 |

## 七、包内组成和验证边界

`runtime/` 与 `packages/` 继承已校验 V2.7 包的 Windows x64 解释器和固定依赖；本轮未重新下载这些二进制，也未将其当作实机测试。`app/` 是运行源码；`source/` 是可单独阅读、测试和重建的便携源码；`MANIFEST.json` 是文件大小与 SHA-256 清单；`provenance/refresh.json` 记录基线包哈希、实际源码清单与运行时继承关系。

程序不会启动时下载依赖，没有 CDN。第三方许可证保留在 runtime 和 packages 原位置。CHECK.log 是本机新生成的日志，不属于发布清单；SHA-256 校验用于检查文件是否变化，不是数字签名。

本轮完成 Linux 应用/API 和真实 Chromium DOM/JS 组件验证，组件测试的 API 响应为测试数据；未完成真实 Windows 10 端到端或生产模型质量验收。详细证据在 source/docs/VERIFICATION_V2.7.1.md。GitHub 源码同步尚未执行成功，不能用默认分支代替本包。

## 八、开发者重建

本包使用一个完全离线、固定输入的刷新构建路径。在独立源码包根目录运行：

```shell
python portable/refresh_v271.py --baseline AstroGraph-LLM-Win10-x64-V2.7-preview.zip --output-dir dist-new
```

V2.7 基线 ZIP 必须匹配 `d6f979721f80be2eff1521ad66cddea2fa12d18bd66067ed80dfabd8fd744fc2`；输出目录必须尚不存在。脚本先验证基线 ZIP 及其清单，保留 runtime/packages，替换源码、说明及测试，生成新的清单和 ZIP。它不访问网络、不需要安装依赖、不导入旧用户 data，也不会覆盖现有安装。

便携源码包内的 src/astrograph 是运行所需的最小模块集合，不是完整 AstroGraph 仓库。**不要把它整个覆盖到完整仓库**。同步完整仓库需按文件审查集成；不要整体替换原 src/astrograph。本轮仅交付便携源码，不改变 GitHub 默认分支。

旧 build.py / prepare_vendor.py 保留为原始构建参考；当前交付复现以 refresh_v271.py 为准。目标机日常使用不需要执行任何构建命令。

## V2.7.1 首次试用微调

- “开始分析”与“测试连接”采用底部粘性操作栏，页面向下滚动时保留主操作；数据发送提示仍可见。必要时继续向下滚动填写其余表单。
- 当前模型位于诊断材料上方；“已填写”不代表“已测试”，“列表接口已连通”也不代表已经验证模型生成能力。
- 材料角色始终可选；文本文件编码默认折叠，旧中文文本可展开选择 GB18030。PDF/DOCX 自动解析，无需指定文本编码。
- 文件详细容量说明默认折叠；主要输入、按钮和报告正文为 14 CSS 像素。页面仍可使用浏览器缩放。
- 多报告先显示综合结论和建议核查，随后显示摘要、解读、假设及对照；单报告仍以分析摘要开始，不额外生成综合结论。导出报告的内容和顺序不改动。
- 本轮仅微调界面和交付版本；分析核心、Windows 运行时/依赖、CHECK.bat 与 START.bat 均沿用 V2.7。目标机无需联网安装依赖或另装 Python、Node。模型服务和权重仍需另备。
- 更新时解压到新目录，CHECK.bat → START.bat。已有任务先备份，再从“历史任务”恢复；不要单独覆盖旧 HTML/JS/CSS，以免破坏旧清单校验。
