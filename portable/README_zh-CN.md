# AstroGraph-LLM 外部诊断文本分析工作台

这是面向 Windows 10 **64 位 x64** 的便携包。完整解压后即可使用，不需要安装 Python、Node、pip、管理员权限或 GPU。界面只做“外部诊断文本 → 大模型解读 → 来源引用与报告”，不运行遥测检测、诊断计算、故障知识图谱或模型训练。

支持两种模型连接方式：联网调用兼容 OpenAI Chat Completions 的 HTTPS API；或调用本机已经启动的兼容 API 模型服务。**本包不含模型权重，也不含模型服务软件。** 界面本身不需要 GPU；本地模型是否需要 GPU、内存和显存取决于您另外准备的模型服务。

## 一、启动

1. 将整个 ZIP 解压到自己有写入权限的文件夹，例如“文档”中的 AstroGraph 文件夹。不要直接在压缩文件窗口内运行，也不要只复制 START.bat。
2. 双击 `CHECK.bat`，执行不连接模型的离线依赖、导入和功能自检。成功时显示 `Offline self-test passed`。
3. 双击 `START.bat`。程序在本机 `127.0.0.1` 启动，并用默认浏览器打开界面。如果浏览器没有自动打开，请复制控制台显示的本机地址。
4. 使用期间保留控制台窗口。退出时在控制台按 Ctrl+C；关闭浏览器标签页不会停止服务。

请使用已经安装的 Edge 或 Chrome。目标为 Windows 10 x64，建议 22H2；不支持 Windows 7、32 位 Windows 或 ARM 版 Windows。解压路径可以含空格和中文，但文件夹必须允许写入。程序不需要以管理员身份运行。

## 二、连接本地离线模型

“离线”表示大模型服务和模型已经在这台电脑上准备好，本程序不负责下载或启动它们。

1. 先在模型服务软件中加载您已经具备的模型，并开启兼容 OpenAI 的本地 API 服务。
2. 在工作台选择“本地模型”。LM Studio 常见地址为 `http://127.0.0.1:1234/v1`；Ollama 常见地址为 `http://127.0.0.1:11434/v1`。实际地址以服务软件显示的值为准。
3. 点击“测试连接”，选择或填写服务实际返回的**模型 ID**。模型 ID 必须与服务中的名称一致，不能填写任意显示名称。
4. 如果本地服务要求 API Key，填写该服务配置的值；若不要求，可按界面提示留空。
5. 导入材料并点击分析。运行速度由模型、电脑和服务设置决定。

本地模式只接受 loopback 地址，例如 `127.0.0.1` 或 `localhost`，不会因为输入了外部地址而悄悄切换到云端。本工作台不会在启动时调用模型、下载模型或下载 Python 依赖。

## 三、连接在线 API

1. 选择“在线 API”，填写供应商提供的 **HTTPS** Base URL，通常以 `/v1` 结尾；本程序请求 `/chat/completions`，测试连接查询 `/models`。
2. 填写 API Key 和该服务实际支持的模型 ID。某些 API 不提供模型列表，测试连接可能失败；请先核对该服务是否兼容本程序使用的接口。
3. 按服务能力设置输出 token 上限、超时和 JSON 响应格式。默认自动策略会尝试兼容的 JSON 格式；最终输出仍会在本机进行结构与来源引用校验。
4. 点击分析后，选中的诊断材料、分析要求以及后续追问会发往您配置的 API。请确认这些材料适合交给该服务处理；调用费用由该服务计费。

API Key 仅在本次服务进程的内存中使用，不写入保存的设置、任务、报告或控制台。刷新或重启后若需要再次调用，请重新输入连接信息和 Key。模型服务端本身如何处理数据，由您使用的服务决定。

## 四、输入、结果与导出

可以直接粘贴诊断文本，或导入 TXT、MD、JSON、CSV、LOG、PDF、DOCX。请将每份材料明确设为“外部诊断”“补充日志”或“参考资料”；至少需要一份外部诊断。LOG 文件归入日志，参考资料使用 TXT/MD/PDF/DOCX。示例位于 `app/examples/diagnosis_sample.txt`，内容为虚构材料。根目录的 `README_zh-CN.txt` 可直接用记事本打开，内容与本文相同。

支持 UTF-8、带 BOM 的 UTF-8/UTF-16；旧中文文本可在导入时明确选择 GB18030。本界面不接受压缩包或原始遥测。PDF 会按页提取文字；DOCX 保留标题、正文、表格及原始定位。PDF 文件采用随包携带的 pypdf 6.21.4 纯 Python 解析器，不依赖 Poppler；扫描版 PDF 不做自动 OCR，需先 OCR 并人工核验。文件名不能重复，也不能使用路径、Windows 保留名或其他不安全名称。

每次任务最多 8 份诊断、12 份日志、16 份参考资料，总输入上限 4 MiB，解析后正文上限 180,000 字符；分析要求上限 4,000 字符。60,000 字符以内使用一次模型分析；超过后最多 24 个连续片段（每段约 12,000 字符、重叠 600 字符）分块分析，再执行一次综合分析。超出容量会明确拒绝，不会静默截断。长文任务会产生多次模型调用，费用和耗时高于短报告，实际可用上下文仍取决于模型服务设置。

结果包含报告内容解读、可能原因及反向解释、前提和不确定性、缺失信息、建议核查和来源引用。点击引用可查看原始段落和位置。可以下载 Markdown/JSON；追问记录也可下载。模型调用或校验失败会显示状态与原因代码，原始材料仍保留；任务已保存并不等于模型分析成功。

追问只使用该任务原始来源，不把问题中的断言或过去模型回答当作新证据。每个任务最多 12 次追问尝试，每个问题最多 4,000 字符；历史上下文有额外容量限制。长报告分块分析会在每个片段通过校验后保存检查点；服务重启后任务显示中断，重新配置相同模型模式、服务地址和模型 ID 后，可点击“继续中断任务”，已完成片段不会重复调用。短报告没有分块检查点，继续时会重新执行整份报告分析。

**引用校验通过只代表引用编号存在于输入材料，不能证明模型解读、假设或原始报告正确。** 所有模型内容均需专业人员结合原始资料复核，不构成已确认故障或设备操作授权。

## 五、数据与常见问题

任务、原始字节副本、规范化文本、报告和追问历史保存在解压目录的 `data/`。历史任务列表旁提供“备份”下载完整 ZIP（包含任务、原始文件、报告、追问和分块检查点），以及“恢复”导入 ZIP。恢复前会校验清单、文件 SHA-256 和路径；同编号任务拒绝覆盖，已有数据不会被替换。备份也可在关闭程序后复制整个解压目录。不要在分析过程中手工修改任务文件。

| 现象 | 处理方式 |
|---|---|
| 提示文件不完整、缺 DLL 或找不到模块 | 重新完整解压；检查安全软件是否隔离了文件；先运行 CHECK.bat。不要用系统 Python 替换随包解释器。 |
| 数据目录不可写 | 移到自己的“文档”等可写位置，避免 Program Files、只读目录或受限共享盘。 |
| 连接拒绝/超时 | 检查模型服务已启动、端口与地址正确、模型已加载；核对本机防火墙和服务日志。 |
| API 认证或模型错误 | 核对 Key、Base URL 和服务实际模型 ID；详细提供商错误不在报告中公开。 |
| 输出过长或结构校验失败 | 增加服务允许的输出 token、缩小本次输入或换用能够遵循 JSON 结构的模型；按需要选择 JSON 格式策略。 |
| 中文乱码 | 导入旧文件时选择 GB18030，或先将文件另存为 UTF-8。 |
| 浏览器不能连接 | 保留控制台窗口，使用其实际显示的本机 URL，检查端口是否已被其他程序使用。 |
| 服务重启后任务显示中断 | 长报告可重新连接原模型后点击“继续中断任务”；短报告重新分析。程序不会自动重放模型请求。 |
| 需要迁移或恢复历史任务 | 点击历史列表旁“备份”下载 ZIP；在目标工作台点击“恢复”选择 ZIP。冲突任务不会覆盖。 |

## 六、包内组成与验证范围

`runtime/` 为官方 CPython 3.14.10 Windows x64 embedded runtime；`packages/` 为预先解包的固定 Pydantic 与 PDF 解析依赖，保留各自 dist-info 和许可证；`app/` 为可阅读的工作台及原项目最小源码；`source/` 为构建脚本、版本锁定和设计/实施说明。没有启动时安装步骤。`runtime/python314._pth` 显式列出相对目录，并关闭自动 site 导入。

`MANIFEST.json` 记录构建来源 commit、文件大小和 SHA-256。`provenance/` 记录官方 Python 来源与 PyPI wheel 校验。发布 ZIP 旁的 `.sha256` 可用于整体校验。Python 许可证位于 `runtime/LICENSE.txt`，其他第三方许可证保留在 `packages/*.dist-info/` 中。

已在 Linux 环境验证最小导入、应用逻辑和本地 HTTP 模型桩流程，并检查 Windows 文件架构、依赖标签、官方哈希及 ZIP 完整性。**尚未在真实 Windows 10 上执行；这些检查不能替代目标机器实测。** 首次使用请运行 CHECK.bat，再实际完成一次连接、分析、引用查看、追问和导出。如应用源有后续修改，验证记录以随包清单和交付说明为准。

本次交付还通过隔离 Chromium 的实际界面流程：示例和文件导入、读取模型列表、分析、引用跳转、追问、Markdown/JSON/对话导出、刷新后恢复历史，以及 API Key 不持久化检查。模型端使用本机测试接口，未评价真实大模型的诊断质量。浏览器未请求远程静态资源。源码同步未确认完成，包内源码可直接阅读与运行；请勿据此认为 GitHub 默认分支已更新。Windows 自动化工作流已经提供，但本次交付未取得该工作流的执行结果。

## 七、复现构建（开发者）

便携新增源码可通过包内 `source/SOURCE_CHANGES.patch` 恢复：在原项目提交 `5389bfd78f8a9f62117f8804eab181fda7557046` 的干净检出上运行 `git apply SOURCE_CHANGES.patch`，即可得到 `portable/`、说明和工作流。运行时源码同时完整保存在 `app/` 中。若浅层 CI 检出没有基础提交，则构建器可能不生成该补丁。

在原项目 checkout 中使用 Python 3.11–3.14 运行构建器。准备官方下载的 `python-3.14.10-embed-amd64.zip`，SHA-256 必须为：

```text
90905e64a840557d8c1bc4f5b74db3d7ee85e3ffb217611cac1c7813acea4159
```

官方下载地址：<https://www.python.org/ftp/python/3.14.10/python-3.14.10-embed-amd64.zip>。在有网络的构建机运行以下准备命令；它下载官方 runtime、固定 Windows wheel，并逐一查询 PyPI 官方 JSON 元数据核对 SHA-256，写出构建器要求的来源记录。**这是开发者明确执行的构建步骤，START.bat 和 CHECK.bat 均不会调用它。**

```bash
python portable/prepare_vendor.py --output-dir vendor
```

确认准备命令成功后运行完全离线的构建器：

```bash
python portable/build.py --runtime vendor/python-3.14.10-embed-amd64.zip --wheels-dir vendor/wheels-win314 --output-dir dist
```

输出目录必须没有同名包或 ZIP，构建器不会覆盖它们。可加 `--source-commit <commit>` 明确记录来源。构建不联网，不执行 pip，不修改原项目核心模块；只复制声明的最小源码，并替换两个包初始化文件以隔离未使用的完整诊断引擎。构建前后应运行项目随附的工作台测试；在 Windows 上再运行 CHECK.bat 和实际模型验收。

仓库中的 `.github/workflows/portable-workbench.yml` 在相关分支推送、Pull Request 或手动触发时，在 `windows-latest` 上运行固定依赖的应用测试、准备并校验构建输入、生成 ZIP，然后将 ZIP 解压到含中文和空格的目录，实际运行包内 embedded Python 的 `--self-test`。通过后可在 GitHub Actions 的 Artifacts 下载便携包；资格检查日志单独保留。该 runner 是 Windows 环境，但不等同于 Windows 10 实机，仍需目标电脑验收。工作流只调用本机模型桩，不使用真实模型服务、API Key 或其他账号密钥。


## 2.6.0-rc.1 交付收敛

本次冻结业务功能，只修复影响使用与恢复的问题。建议完整解压至新目录，保留旧版 data；在旧版无任务运行时执行备份，再在新版恢复。

先双击 CHECK.bat。它校验清单中的文件，再运行真实本机 HTTP 模拟模型自检；结果保存到 `data/diagnostics/installation-check.json`。这个文件不包含 API Key 或诊断正文，可用于反馈安装问题。自动化运行可使用 `CHECK.bat --no-pause`。

通过后双击 START.bat，填写本地或在线连接，载入示例并完成分析、引用、追问、导出。模型权重和模型服务仍由用户提前准备；在线模式会把所选材料发送给配置的服务。

恢复导入的未完成任务现在立即标记为“中断”，可重新输入原模型连接后续跑。分析或追问运行期间拒绝备份/恢复，避免生成不一致快照。续跑会重新核对保存材料的实际内容哈希。

长报告综合不再静默截取每段摘要。若完整片段摘要累计超过 60,000 字符，会明确返回 `SYNTHESIS_CONTEXT_TOO_LARGE`；已完成分块仍保存，用户可拆分材料重新分析。对照结论的引用现已统一映射到原始来源。

构建依赖锁定 pypdf 6.21.4；必须从 PyPI 下载并核对官方 SHA-256 后才能打包。升级本身不构成安全认证。

本版本为发布候选。Windows Server CI、Windows 10 实机运行和实际模型质量是三个独立验收项；只以本次交付的验证记录为准，不把其中一项代替其他项。
