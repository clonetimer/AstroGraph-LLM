# AstroGraph 使用步骤

AstroGraph 是一个面向航天器故障研判的本地 Web 工作台。用户可以上传已有诊断结果、运行日志和参考文献，选择规则引擎或已配置的大模型生成原因分析、证据说明和处置建议，再由领域专家完成复核。

> 系统输出用于辅助研判，不代表故障已经工程确诊，也不会自动向设备下发控制指令。

## 1. 运行环境

- Windows 10/11，PowerShell 5.1 或 PowerShell 7
- Python 3.11～3.14
- [uv](https://docs.astral.sh/uv/)
- Chrome 或 Edge
- 如需真实浏览器验收，需要安装 Playwright Chromium
- 如需使用远程大模型，需要本机能够通过 SSH 访问模型服务器

以下命令均在本文件所在的 `source` 目录中执行。

## 2. 创建 Python 环境并安装依赖

```powershell
uv venv .venv
.\.venv\Scripts\Activate.ps1
uv pip install -e ".[platform,test]" playwright
python -m playwright install chromium
```

如果 PowerShell 不允许执行激活脚本，可以不激活环境，后续把 `python` 换成：

```powershell
.\.venv\Scripts\python.exe
```

安装完成后可以确认解释器：

```powershell
python --version
python -c "import astrograph; print('AstroGraph 已安装')"
```

## 3. 启动前检查

先检查 Windows 启动和验收脚本是否能被 PowerShell 正确解析：

```powershell
.\verify_powershell_scripts.ps1
```

所有项目均显示 `PASS` 后再继续。

## 4. 以账户模式启动

建议为每轮正式试用指定独立的数据目录。任务、账号、配置和审核记录都会保存在该目录中。

```powershell
$env:ASTROGRAPH_PLATFORM_ROOT = Join-Path $PWD "runs\command-center"
$env:ASTROGRAPH_PORT = "8081"
.\run_platform_accounts_demo.ps1
```

首次使用新的数据目录时，终端会要求输入一个至少 24 个字符的“管理员初始化密钥”。输入时字符不会显示，这是正常现象。请在服务运行期间保留这个终端窗口。

浏览器访问：

<http://127.0.0.1:8081/platform>

如果 8081 已被占用，可把 `ASTROGRAPH_PORT` 改为其他端口，并同步修改浏览器地址。

### 继续使用原有账号和任务

再次启动时使用相同的 `ASTROGRAPH_PLATFORM_ROOT`：

```powershell
$env:ASTROGRAPH_PLATFORM_ROOT = Join-Path $PWD "runs\command-center"
```
已有账户的用户名和密码由管理员自行设定；本项目不提供默认登录凭据。请勿将测试账户凭据写入 README 或提交至版本库。

如果换成新的目录，系统会把它视为全新环境，需要重新初始化管理员。

## 5. 首次创建管理员

系统没有预设用户名和密码。首次打开页面时：

1. 在“初始化系统管理员”窗口填写自定义管理员账号。
2. 填写管理员显示名称。
3. 设置至少 12 位的登录密码。
4. 输入启动服务时在 PowerShell 中设置的管理员初始化密钥。
5. 点击“创建管理员并登录”。

初始化密钥只用于创建第一个管理员，不能代替日常登录密码。

## 6. 创建分析人员和领域专家账号

管理员登录后：

1. 打开左侧“人员与访问”。
2. 填写登录账号、显示名称和至少 12 位的临时密码。
3. 选择角色并点击“创建账号”。

角色权限如下：

| 角色 | 主要用途 |
| --- | --- |
| 只读用户 | 查看允许访问的任务、报告和知识内容 |
| 分析人员 | 新建分析、上传材料、生成报告 |
| 领域审核专家 | 查看报告并提交人工复核，也可参与文献建图和知识审核 |
| 平台管理员 | 管理用户、模型及知识引擎配置，并拥有其他工作权限 |

管理员可以在同一页面修改角色、停用账号或重置密码。系统不提供通用测试密码，请使用自己创建的账号。

## 7. 配置远程 vLLM 大模型

### 7.1 建立 SSH 隧道

另开一个 PowerShell 窗口，在本机执行：

```powershell
ssh -fN -L 8091:127.0.0.1:8000 a@10.100.182.135
```

这会把远程服务器的 `127.0.0.1:8000` 映射到本机 `127.0.0.1:8091`。先确认隧道可访问，再配置 AstroGraph：

```powershell
Invoke-RestMethod http://127.0.0.1:8091/v1/models
```

如果命令失败，应先检查 SSH 登录、远程 vLLM 服务和端口，而不是反复保存模型配置。

### 7.2 在界面保存模型

使用管理员账号打开“模型与引擎”，填写：

| 字段 | 示例 |
| --- | --- |
| 服务类型 | `vLLM` |
| 服务地址 | `http://127.0.0.1:8091/v1` |
| 模型标识 | `qwen3-9B`，必须与 `/v1/models` 返回的 ID 一致 |
| 密钥 | vLLM 未启用鉴权时留空 |

然后按顺序操作：

1. 点击“检测模型”。
2. 确认目录、普通对话和结构化输出检查均通过。
3. 勾选“保存为默认服务（重启后可用）”。
4. 填写容易识别的配置名称，例如“远程 Qwen3 9B”。
5. 点击“保存设置”。

可以重复以上步骤保存多个大模型配置。每个已保存配置都会出现在“新建分析”的处理引擎菜单中。

## 8. 完成一次新建分析

使用分析人员、领域专家或管理员账号操作：

1. 打开左侧“新建分析”。
2. 用自然语言描述问题，例如：

   > 请结合诊断结果、运行日志和参考资料，判断最可能的故障原因，说明证据是否充分，并给出下一步核查建议。

3. 点击回形针“添加材料”，分别上传以下三类文件：
   - 诊断结果：诊断软件或算法产生的 JSON、CSV、TXT、Markdown、PDF 或 DOCX。
   - 运行日志：LOG、JSON、CSV、TXT、Markdown、PDF 或 DOCX。
   - 参考资料：TXT、Markdown、PDF 或 DOCX 文献、手册或规程。
4. 在“处理引擎”中选择本次任务使用的引擎：
   - “规则引擎”：无需配置大模型，可生成确定性的证据整理与规则研判结果。
   - 已保存的大模型：调用指定模型综合诊断、日志、上传文献及内部已审核图谱文献。
5. 等待自动预检完成。如果材料角色错误或缺失，按页面提示补充。
6. 点击“开始分析”。
7. 等待处理完成，页面会进入同一任务的研判工作台或决策报告。

每个任务会固定记录创建时选择的引擎。之后修改默认模型，不会把已完成任务悄悄切换到另一个模型。

## 9. 查看分析结果

“决策报告”按用途分为四部分：

1. “研判结论”：查看当前判断、证据充分程度、风险和下一步建议。
2. “日志与文献”：查看引用片段、原文件和原文位置。
3. “图谱推理”：查看内部已审核知识图谱提供的关联路径。
4. “审核与溯源”：查看任务编号、材料摘要、处理引擎和人工复核状态。

选择大模型后，报告会额外显示“大模型综合处置结果”，包括：

- 综合判断；
- 原因与引用依据；
- 建议的处置及核查步骤；
- 模型局限和人工审批边界；
- 上传文献命中数、内部图谱路径数和引用检查状态。

只有通过结构和引用校验的大模型内容才会展示。如果模型未配置、调用失败或引用检查未通过，页面会明确说明原因，并保留规则引擎结果作为可复核基线。

需要留档时，可点击“下载文字报告”；“更多”中可以导出完整数据。

## 10. 参考文献和内部图谱文献

系统中的“文献”包含两类来源：

1. 本次分析上传的参考资料，仅用于当前任务的证据检索。
2. 软件内部已经经过审核并进入知识图谱的文献关系，可被后续任务重复使用。

新上传的文献不会自动变成已审核图谱知识。需要复用时，由领域审核专家执行：

1. 打开“文献建图”。
2. 填写设备型号或构型并上传文献。
3. 点击“构建候选图谱”。
4. 打开“知识审核”，逐项核对候选实体、关系和原文引用。
5. 审核通过并发布后，相关知识才进入后续任务可使用的内部图谱。

## 11. 专家复核报告

使用领域审核专家或管理员账号登录：

1. 打开“待复核事项”。
2. 从队列中选择已完成任务。
3. 对每个故障候选选择“证据不足”“支持继续排查”或“不支持候选”。
4. 填写独立核验依据。
5. 填写至少 8 个字的具体复核说明。
6. 保存复核记录。

账户模式下，专家身份来自真实登录账号，不需要另外输入固定的“专家密码”。

## 12. 运行验收测试

保持平台服务运行，在另一个已经激活同一 Python 环境的 PowerShell 窗口中执行：

```powershell
.\run_p0_acceptance_windows.ps1
.\run_p0_acceptance_windows.ps1 -RealBrowserHTTP
.\run_acceptance_cases.ps1
```

- 第一条检查账号、上传、预检、报告、事件中心和复核主流程。
- 第二条增加真实 Chromium HTTP 测试。
- 第三条运行内置合成案例，结果写入 `runs\acceptance_cases`。

测试失败时请保留 PowerShell 输出、浏览器截图及 `runs` 下对应任务目录，便于定位问题。

## 13. 停止服务

回到运行 `run_platform_accounts_demo.ps1` 的 PowerShell 窗口，按 `Ctrl+C`。看到命令提示符重新出现后，服务即已停止。

SSH 隧道是独立进程，停止 AstroGraph 不会自动关闭隧道。如不再使用，请根据本机实际 SSH 进程单独关闭，不要直接结束所有 SSH 会话。

## 14. 常见问题

### 页面仍显示旧界面

先停止并重新启动服务，再在浏览器中按 `Ctrl+F5` 强制刷新。

### 忘记用户名或密码

系统没有默认账号。管理员可在“人员与访问”中查看用户名并重置其他用户密码。若唯一管理员密码丢失，请先备份当前数据目录，不要直接删除账号数据库。

### “新建分析”中没有大模型选项

确认管理员已经勾选“保存为默认服务（重启后可用）”、填写配置名称并保存。仅临时填写但未持久化的配置不会作为稳定的多模型选项使用。

### 大模型检测失败

依次检查：

1. `http://127.0.0.1:8091/v1/models` 是否可访问；
2. SSH 隧道是否仍在运行；
3. 远程 vLLM 是否监听 `127.0.0.1:8000`；
4. 模型标识是否与 `/v1/models` 返回值完全一致；
5. 模型是否支持 AstroGraph 所需的结构化 JSON 输出。

### 不配置大模型能否使用

可以。在“新建分析”中选择“规则引擎”即可。上传材料、证据定位、规则研判、报告导出和人工复核仍然可用。

### 为什么报告没有直接给出确定根因

当材料缺失、证据互相矛盾或引用无法支持结论时，系统会保留“证据不足”或待复核状态。这是为了避免把模型推测当成已经证实的工程事实。

## 附录：耗时测试采用日志文件与完成标记

为了避免在交互终端持续打印输出，可用独立进程执行长时间验证（Windows PowerShell / Linux 均可用）：

```powershell
python scripts/launch_logged_tests.py start --timeout 600 foundation-smoke -- python -m pytest -q tests/test_document_claim_fusion_adapter.py
python scripts/launch_logged_tests.py status foundation-smoke
```

启动命令立即返回；完整标准输出/错误输出写入 `validation_logs/foundation-smoke/output.log`。作业结束会**原子写入** `validation_logs/foundation-smoke/done.json`，包含退出码、结束时间与日志路径。CI 或外部文件监视器可以将 `done.json` 作为完成触发条件；它不会自行向 ChatGPT 会话推送消息。若需要复跑，请使用新的作业名称，避免覆盖历史日志。出现 FAILED 或超时必须检查日志，不能按 PASS 处理。正式验收应额外校验原始数据与 SHA256 清单。
